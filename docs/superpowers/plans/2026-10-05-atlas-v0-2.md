# Arabic AI Atlas v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Most-Wanted board (A) and the Family tree (B) in full, bump the plugin to 0.2.0, and lay down skeletons plus follow-up spec pointers for the Arabic-ready badge (C) and Model Passport (D).

**Scope note:** A and B are built end to end here (Tasks 1-9), plus the shared items (Task 10). C and D get one task each (Tasks 11-12) that creates a tested skeleton and a follow-up spec stub; their full builds (code search for badge users, the 12 probes, inference runner, passport rendering, `recommend(min_passport=...)`) need their own plans written from those follow-up specs.

**Architecture:** Every new output is a pure renderer called from `render_outputs()` in `scripts/build.py`, so `build --check` drift-checks it byte for byte. Gap rules live in `data/wanted.yaml` and are evaluated by `atlas/wanted.py`; their fill dates live in `data/.cache/wanted.json`, which is itself a render output. Lineage is computed once in Python (`atlas/lineage.py`) and published as a top-level `lineage` object in `dist/atlas.json`, which the SVG renderer, the site Tree view and the MCP `lineage` tool all read, so the root-family regex exists in one place.

**Tech Stack:** Python 3.11+ stdlib + pyyaml + jsonschema (uv, pytest), vanilla JS site with vendored D3 7.9.0 (already includes `d3.tree`/`d3.hierarchy`, no new vendor file), MCP SDK `mcp>=2,<3`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-05-atlas-v0-2-design.md`

## Global Constraints

- `data/` is the only hand-edited source; never hand-edit `README.md`, `docs/tables/`, `assets/`, `dist/`. Regenerate with `uv run python scripts/build.py build` (never `all` locally; it refetches HF metrics, nightly only).
- Every generated output stays drift-checked: it must be produced by `render_outputs()` so `uv run python scripts/build.py build --check --skip-enrich` covers it.
- Renderers are deterministic: no clock, no randomness, everything sorted; the only date is the `generated_at`/`--date` passed in.
- SVGs are stdlib only and carry light and dark styles (`@media (prefers-color-scheme: dark)`), as `atlas/render_geo.py` does.
- Site stays dependency-free beyond `site/vendor/`; no CDN scripts (`tests/test_site.py::test_no_remote_scripts_or_cdns` must keep passing).
- Snapshot tests update only with `UPDATE_SNAPSHOTS=1 uv run pytest ...`, and the snapshot diff is read before committing.
- Wanted rule `why` is at most 160 characters; `license_class` is `open` or `any`; `open` means license class is open: not `proprietary`/`unknown`/empty and no `nc`/`noncommercial`/`non-commercial` (the same rule as `licenseClass` in `site/app.js`).
- Recently filled rules stay listed for 30 days after `filled_on`; `filled_on` lives in `data/.cache/wanted.json`, never in YAML.
- `base_model` is optional, a list of strings, allowed only on model types (`llm`, `asr`, `tts`, `ocr`, `embedding`). YAML value wins; the HF cache fills gaps.
- Root families, matched in this order: whisper, mms, xlsr, wav2vec, electra, bert, t5, llama, qwen, gemma, mistral, falcon, bloom, phi, deepseek, from-scratch; anything else is `other`.
- Plugin version 0.2.0 in `.claude-plugin/plugin.json` and `pyproject.toml`.
- Commits: conventional prefix (`feat:`, `data:`, `docs:`, `chore:`, `test:`), plain message, no `Co-Authored-By` or other trailers. Do not push.

## Review Focus

1. `data/wanted.yaml` sitting in `data/` gets slurped by `atlas.load.load_entries` (it globs `*.yaml`) and fails schema validation for every rule. Expect: it is skipped as an entry file and validated as rules instead. Test: Task 1 `test_load_entries_skips_wanted_yaml`.
2. A rule with a typo key (`dialect:` instead of `dialects:`) or an empty `query` silently matches everything and shows as filled forever. Expect: `build.py validate` fails naming the rule. Test: Task 1 `test_validate_rules_rejects_unknown_key_and_empty_query`.
3. A filled rule becomes unfilled again (the entry is deleted or its license turns non-commercial). Expect: it returns to Most Wanted and its cache row is dropped, so a later fill gets a fresh `filled_on`. Test: Task 2 `test_unfilled_again_returns_to_board`.
4. `base_model` chains that loop (A says B, B says A, or a model naming itself, which happens on HF cards). Expect: lineage terminates, both nodes get root `other`, and `lineage(id)` returns finite lists. Test: Task 7 `test_cycle_terminates`.
5. `base_model` values arrive in mixed forms: a full HF URL, mixed case, a `cardData.base_model` string or list, tags like `base_model:finetune:meta-llama/Llama-2-7b`, or an atlas id. Expect: all normalize to one lowercase id and resolve to the atlas entry when one exists. Tests: Task 5 `test_card_base_models_forms`, Task 7 `test_base_resolves_by_hf_url_and_atlas_id`.

  - `atlas.render_wanted.render_wanted_block(statuses: list[dict]) -> str` (README body under `## 🎯 Most Wanted`).
  - `atlas.render_wanted.render_wanted_table(statuses: list[dict], generated_at: str) -> str` (full `docs/tables/wanted.md`).
  - `atlas.render_readme.render_readme(merged, template, generated_at, shipped_skills, blocks: dict[str, str] | None = None) -> str`: replaces `{{KEY}}` for each key in `blocks`, and any of `{{WANTED}}`, `{{TREE}}` left unreplaced become `""`.
  - `atlas.render_json.build_atlas_json(merged, generated_at, extras: dict | None = None) -> dict`: `extras` keys are added after `entries`.
  - New render outputs: `docs/tables/wanted.md`, `data/.cache/wanted.json`, and atlas.json key `wanted` (list of statuses without `query`).
